1. Executive Summary & Product Vision

TubeListiFy merges and revitalizes two of your existing repositories: yt-spot (the visual concept for bidirectional YouTube-Spotify conversion) and billboard-to-spotify (the Python Billboard chart web-scraper).

The objective is to transform these isolated scripts into a production-ready, high-performance web platform that stands out on your resume as a full-stack engineering achievement. TubeListiFy solves real technical challenges: OAuth2 token lifecycle coordination, rate-limit-aware batch synchronization, and high-accuracy fuzzy string matching to clean up raw YouTube video titles into canonical music metadata.

Feature A: Bidirectional Playlist Sync

One-click transfer from YouTube to Spotify and Spotify to YouTube Music with smart song matching, confidence scoring, and interactive dispute review.

Feature B: Billboard "Time Capsule"

Interactive date-picker allowing users to pull any Billboard Hot 100 chart from 1958 to present day and generate instant playlists in seconds.

3. System Architecture

TubeListiFy utilizes a modern full-stack decoupled architecture designed for speed, resilience against third-party API rate limits, and seamless cloud deployment.

[Client: Next.js 14 Web UI] │ ├──▶ [Next.js App Server / API Routes] │ ├── Auth Controller (Spotify OAuth2 + Google OAuth2 PKCE) │ ├── Pipeline Dispatcher (Transfer Coordinator) │ └── Scraper Engine (Billboard Hot 100 Parser + Cache) │ ├──▶ [Metadata & Matching Service] │ ├── String Normalizer (Regex Noise Stripper) │ ├── Fuzzy Matcher (Token-Sort Ratio + Duration Delta ≤ 5s) │ └── Confidence Score Classifier (High ≥ 85% | Needs Review < 85%) │ └──▶ [External Platforms] ├── Spotify Web API (Playlists, Search, Library Write) ├── Google YouTube Data API v3 (PlaylistItems, Search) └── Billboard.com (Historical Weekly Chart Archives)

4. Technology Stack Comparison & Selection

Option A: Unified Next.js 14 Full-Stack (Recommended)

  • Frontend: React 18 / Next.js 14 App Router, Tailwind CSS, Lucide Icons, Shadcn UI.
  • Backend: Next.js Server Actions & Route Handlers (Node.js runtime).
  • APIs: spotify-web-api-node, googleapis (YouTube v3).
  • Scraper: cheerio + axios for Billboard parsing.
  • Deployment: Single-click zero-config on Vercel.
  • Verdict: Fastest to deploy, unified TypeScript types, exceptional developer experience.

Option B: Next.js UI + FastAPI Python Backend

  • Frontend: Next.js 14 / TypeScript on Vercel.
  • Backend: FastAPI (Python 3.13) + Uvicorn + Pydantic.
  • APIs: spotipy, google-api-python-client, yt-dlp.
  • Scraper: beautifulsoup4 + httpx.
  • Deployment: Frontend on Vercel; Backend on Railway/Render.
  • Verdict: Leverages your existing Python billboard script directly; slightly higher deployment complexity.
Selected Strategy: We will structure the project as Option A (Unified Next.js 14 Full-Stack) for seamless hosting and instant live demo availability, while keeping the core song-matching and Billboard scraping algorithms modular so they can be run via CLI or embedded seamlessly into API routes.
